## How the pieces fit

TriageLab runs beside kagent and Agent Substrate on a dedicated cluster.
kagent runs the investigator agent and its model, Agent Substrate provides the
isolated sandbox (gVisor or microVM, with egress denied by default), and
TriageLab handles everything between the ticket and the report. The Go CLI and
the browser workspace share one workflow: you can submit a description and
files yourself, or let a ticket source start the case. Inputs are capped at 64
files, 1 MiB per file and 4 MiB in total, and unsafe inputs are rejected before
anything is transferred.

## Why approval comes first

The steps before the sandbox keep untrusted ticket content away from the model
until a person has seen exactly what will run: the sanitized facts, file
hashes, chosen agent, and run limits. Approval expires quickly and is checked
again at launch, so an outdated plan cannot start. Inside the sandbox, the hard
limits come from upstream isolation and egress policy, not from the prompt.

## Status and scope

TriageLab is an early, single-user pilot, not a production support platform.
The workflow is general, but the only procedure that ships with it is a Python
3.12 timeout reproduction. Admins add procedures for other kinds of tickets in
the workspace. There is no database, operator, custom sandbox runtime, or
agent framework, and nothing is simulated. A failed run keeps its partial
report, so a nonzero exit code is no reason to discard it. Infrastructure
failures are never reported as "not reproduced."
