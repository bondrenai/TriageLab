TriageLab 0.1.0 is out: the Go CLI, the browser workspace, the evidence-first
investigation workflow, and the first public Helm chart
(`oci://ghcr.io/bondrenai/charts/triagelab`) for running the single-user
workspace as one pod beside an existing kagent/Substrate installation.

What shipped in this release:

- **The core loop** — collect a bounded case, create one standalone sandbox,
  start one real kagent investigator, record experiments independently, and
  write JSON and Markdown reports that separate observed evidence from model
  hypotheses.
- **The browser workspace** — loopback-only and authenticated, with local
  accounts or one OIDC provider, viewer/user/admin roles, and editors for
  kagent agents, models, MCP servers, sandbox templates, and egress policies.
- **Ticket and issue sources** — Zendesk, GitHub, and Linear case preparation
  with policy-checked clarifications, input and output sanitizers, and
  review of the exact evidence for launches from the ticket queue.
- **Telemetry** — optional OTLP/HTTP export of traces, metrics, and logs,
  verified against a real collector.

This site is new too. The [reference section](/TriageLab/reference/cli/) includes pages
generated directly from the CLI's flag registrations and configuration
structs, so the technical bits cannot quietly drift from the code — a test
fails if they do. Long-form pieces live under
[articles](/TriageLab/articles/evidence-not-answers/), and release and working notes
will land here on the blog.

Try the [quickstart](/TriageLab/start/quickstart/) on a disposable cluster, and read
[evidence, not answers](/TriageLab/articles/evidence-not-answers/) for why the report
looks the way it does.
